# PRESENTATION_CONTENT.md — контент слайдов PicPac «Момент» (≤10 слайдов, демо 5–7 минут)

Ключевая фраза: **«Сначала закрыли обязательный путь ТЗ, затем усилили его».**
Правило: не называть демо-функции готовыми интеграциями. Треки 1 и 3 не заявляем.

## 1. Проблема
От снимков в телефоне до готовой фотокниги путь длинный: много шагов, непонятно, сколько фото нужно и как получится результат. Проект бросают на середине.
*Показать:* одну фразу и иллюстрацию пути «фото → заказ».

## 2. Решение
Мобильное приложение (Telegram Mini App, браузер, PWA): **Фото → Автомакет → Правки → Проверка → Тестовый заказ → Статус.** Три продукта на одном движке: фотокнига, настенный календарь, печать фото.

## 3. Живое демо (3 минуты)
1. Главная → «Создать фотопродукцию» → карточка шаблона «Свадебная фотокнига».
2. Загрузка 10+ фото, счётчик «N фото · мин. 10».
3. Автомакет с оформлением шаблона, листаем развороты.
4. Редактор: двигаем кадр пальцем, зажимаем фото — видим оригинал.
5. Проверка: предупреждения о тёмных, размытых, дубликатах, «Улучшить» или «Заменить».
6. Корзина → доставка → промокод TEST10 → тестовый заказ (деньги не списываются).
7. Оператор переводит статус → клиент видит новый статус.

## 4. Умные функции
- Предпечатная проверка: разрешение под формат, резкость, свет, дубликаты, риск обрезки.
- Автомакет по дате съёмки, 5 оформлений страниц, Smart Story (закрепить кадр, убрать без удаления).
- Нейросети на своём сервере, фото никуда не передаются: улучшение качества, удаление объекта, удаление фона, генерация кадра.

## 5. ИИ-помощник и Mary
- В приложении: помощник Робо отвечает про заказ, цены, сроки, количество фото, шаблоны и ведёт по ссылкам.
- Архитектура готова к Mary (maryrose.by, платформа ИИ-агентов): сервер выбирает провайдера, Mary получает обезличенный контекст, при сбое отвечает локальный режим.
- **Сейчас работает демо-режим.** Mary подключается после выдачи официального API и ключа.

## 6. Надёжность и данные
Автосохранение черновика, повтор заказа без дубля (Idempotency-Key), понятные ошибки при обрыве связи, роли на сервере, журнал действий, подписанные ссылки на фото, удаление данных по кнопке.

## 7. Качество (цифры только проверенные)
- 29 автотестов API, все зелёные.
- Живой аудит стенда: 50 проверок по ТЗ, все PASS.
- Чистая установка по README и тесты ≈ 21 секунда.
- Экраны проверены на ширинах 360 и 375 px.

## 8. Архитектура
FastAPI + SQLite (WAL) + фронтенд без сборки. Один интерфейс для Telegram, браузера и PWA; оболочка для iOS/Android (Capacitor) подготовлена. Каталог, шаблоны и цены — из API (сейчас mock).

## 9. Что нужно для пилота
API каталога и шаблонов picpac.by, тестовый контур заказов, доступ к Mary, постоянный сервер вместо стенда на ноутбуке, push-уведомления.

## 10. Итог
Обязательный путь ТЗ закрыт и проверен автотестами; сверху — шаблоны, календарь, нейросети и помощник. Следующий шаг — подключить реальные данные picPac и Mary.

## Честные ограничения (держать в голове для вопросов)
- Шаблоны и каталог — тестовые данные (mock API), не реальная выгрузка picpac.by.
- Mary не подключена, помощник в демо-режиме.
- Заказ тестовый, в производство не уходит, оплаты нет.
- Стенд работает на ноутбуке через Tailscale; есть запасная запись экрана.
