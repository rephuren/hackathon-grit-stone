# PicPac Mini App — прототип мобильного заказа фотопродукции

Трек 2 хакатона «Фотопринт»: путь клиента **фото → автомакет → проверка → тестовый заказ → статус** со смартфона.
Интерфейс работает **внутри Telegram (Mini App)** и **в обычном мобильном браузере** (для жюри: открыть по ссылке, без Telegram).

> Данные и цены **синтетические** (ориентир — публичные цены picpac.by). Оплата не списывается. Реальных персональных данных нет.

## Запуск за 3 минуты

```bash
cd app
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn backend.main:app --port 8000
# открыть http://localhost:8000 (лучше в мобильном режиме браузера)
```

Тесты (нужны для воспроизводимости): `.venv/bin/python -m pytest -q`

### Учётные записи
| Роль | Как войти |
|---|---|
| Гость | кнопка **«Начать без регистрации»**: отдельное изолированное пространство; потом можно **«Создать аккаунт»** в Профиле, проекты и заказы перейдут в него |
| Клиент | регистрация в приложении (логин от 3 символов, пароль от 6) или общий демо-аккаунт `demo`; пароль в `app/.env` (`DEMO_PASSWORD`), сброс в чистое состояние: `python scripts/reset_demo.py` |
| Оператор (модерация и производство) | логин `operator`, пароль в `app/.env` (`OPERATOR_PASSWORD`) |

На **публичном стенде** `.env` содержит `SEED_TEST_USERS=0`, случайные пароли и не публикуется; логины и пароли передаются жюри отдельно, не в репозитории.
Только для локальной проверки на чистой базе (`SEED_TEST_USERS=1`, по умолчанию) создаются учётки `demo`/`demo123`, `demo2`/`demo123`, `operator`/`operator123`: **на публичный адрес их выставлять нельзя**.

Автоматическая проверка живого стенда по всем пунктам: `.venv/bin/python scripts/audit_live.py https://адрес-стенда`. Итоги аудита: `docs/08-audit.md`.

### Сценарий проверки (5 минут)
1. **Начать без регистрации** (или войти) → **Каталог** → «Фотокнига Premium» → **Создать проект**.
2. **Фото:** загрузить 10+ фото (подойдут снимки с телефона, HEIC тоже работает). Файл не-картинка будет отклонён с понятной причиной.
3. **Макет:** «Собрать автомакет» — фото раскладываются по страницам и группируются по дате съёмки.
4. **Проверка:** предупреждения о тёмных, размытых, мелких фото и дубликатах; «Улучшить», «Заменить», «Удалить» или продолжить осознанно.
5. **Доставка:** пункт выдачи на карте (OpenStreetMap) или Белпочта/курьер; получатель и телефон.
6. **Заказ:** промокод `TEST10` (−10%) или `FREESHIP`; включите галочку «Демо: обрыв связи» и оформите заказ, затем нажмите «Повторить оформление»: **второй заказ не создаётся**.
7. Выйти → войти как `operator` (пароль из `.env`) → **Заказы** → переводить по этапам: Модерация → Производство → Готов → Завершён. Клиент видит статусную ленту (обновляется сама).
8. **Журнал** и **Воронка** у оператора; у клиента **Профиль → Удалить мои данные**.

| Цена пересчитывается (МП-04) | только на сервере, по опциям, количеству, доставке, промокоду |
| Идемпотентность заказа (МП-05) | заголовок `Idempotency-Key`; повтор возвращает тот же заказ |
| Удаление данных (МП-06) | `DELETE /api/me/data` |
| Предпечатная проверка | `GET /api/projects/{id}/check` |
| Статусная лента, история, поддержка по заказу | экран заказа; `POST /api/orders/{id}/tickets` |
| Две роли с серверной проверкой (ОТ-02) | клиент / оператор; отказ фиксируется в журнале |
| Журнал действий (ОТ-04) | таблица `audit`, виден оператору |
| Обработка ошибок сети (ОТ-05) | экран «Нет связи», повтор без дубликатов; в профиле можно имитировать офлайн |

## Формулы и правила (ОТ-07)
- Деньги хранятся в **копейках**, валюта **BYN**; время в **UTC** с часовым поясом.
- Книга: `цена = база(размер) + (страниц − базовые) / 2 × доплата за 2 страницы`, затем `× экземпляры`.
  Печать фото: `цена за фото × число фото × копии`.
- Скидка `TEST10` = 10% от суммы товаров. Доставка: ПВЗ 4,90; Белпочта 5,90 (бесплатно от 150 руб. после скидки); курьер 9,90. `FREESHIP` обнуляет доставку.
- Требуемое разрешение: `ceil(длинная сторона страницы, см × доля / 2,54 × 150 dpi)`; доля = 0,6 для книги, 1,0 для отпечатка.
  Пример: книга 21×30 → 1063 px по длинной стороне фото.
- «Размытый» кадр: дисперсия лапласиана < 25 (на кадре, уменьшенном до 512 px). «Тёмное»: средняя яркость < 45 из 255.
  «Дубликат»: расстояние Хэмминга перцептивного хэша ≤ 4 при близких яркости и пропорциях.
- Автомакет: фото равномерно распределяются по страницам (до 4 на страницу), сортировка по дате съёмки (EXIF), шаблон зависит от числа и ориентации.

## Безопасность
- Пароли: PBKDF2-SHA256 (120 000 итераций, соль). Токены сессий хранятся как SHA-256, срок 14 дней.
- Вход через Telegram: подпись `initData` проверяется HMAC от токена бота; подделать `user.id` нельзя (есть тест).
- Перебор пароля: 8 неудачных попыток на пару «логин + адрес» за 10 минут, затем ответ 429 с понятным текстом; общий лимит 40 по адресу; регистрации не чаще 20 за 10 минут. Счётчик хранится в памяти процесса.
- Гость → аккаунт: проекты, фото, заказы и обращения гостя переносятся только по его действующему токену и только из гостевого аккаунта (чужой аккаунт перенести нельзя, есть тест).
- Чужие проекты и заказы возвращают 404 (защита от перебора идентификаторов); права оператора проверяются на сервере.
- Фото отдаются только по **подписанным ссылкам** на 1 час. Загрузка перекодируется в JPEG, **EXIF и геометки удаляются**; защита от «бомб декомпрессии».
- Секреты только в переменных окружения (`.env.example`), в репозитории их нет.
- Журнал не содержит содержимого фото и паролей.

## Известные ограничения прототипа
- Один процесс и SQLite: для пилота нужна PostgreSQL и очередь задач. Ограничение частоты есть только для входа и регистрации (в памяти процесса), для остальных запросов его нет.
- «ИИ» в прототипе: проверка качества, автомакет и автоулучшение сделаны **классическими алгоритмами (Pillow)**, внешние AI-API не используются. Локальная генеративная правка (замена фона, `rembg`) и подписи через vision-модель — следующий шаг.
- Простой хэш для дубликатов даёт ложные срабатывания на очень похожих кадрах; серию кадров лучше сравнивать более сильными признаками.
- Карта использует публичные тайлы OpenStreetMap (нужен интернет); адреса и координаты ПВЗ условные.
- Оператор переводит статусы вручную (имитация производства Фотопринта); реальных интеграций ERP/платежей нет.
- Не проверено на реальных iPhone/Android внутри Telegram и на медленных сетях.

## Редактор фото и AI-студия (v2)
- Правки неразрушающие: оригинал хранится отдельно, правки — JSON; «Сбросить всё» возвращает оригинал. Фильтры, яркость/контраст/насыщенность, кадр (пропорции, масштаб, сдвиг), поворот/зеркало, подпись, автоулучшение — Pillow, локально.
- «Убрать фон» (необязательно): `pip install onnxruntime numpy`, затем `python scripts/fetch_models.py` (модель u2netp, Apache-2.0). Без этого кнопка скрыта. `GET /api/capabilities` показывает, что доступно.
- AI-студия «Создать»: **локальная модель** LCM Dreamshaper v7 (MIT) на сервере, описание переводится на английский локальной моделью opus-mt-ru-en; наружу ничего не уходит. Установка: необязательные пакеты из `requirements.txt` и `python scripts/fetch_models.py imagegen` (≈5,5 ГБ). Кадр 768×768 рисуется за секунды на GPU Apple; модель занимает 3–4 ГБ памяти и выгружается после `IMAGEGEN_IDLE_MIN` минут простоя (по умолчанию 15). Генерации идут по одной; включён фильтр недопустимого контента. Созданные кадры хранятся на сервере (последние 12 на пользователя) и не теряются при выходе из приложения.
- Без локальной модели (или с `IMAGEGEN_LOCAL=0`) используется запасной бесплатный Pollinations: уходит только переведённый текст описания; ограничение сервиса 1 картинка в 45 секунд на адрес и возможный водяной знак. Внешний вариант отключается `AI_GENERATE=0`.
- Оформление: макет команды из 8 экранов + VISUAL SPEC «Момент» 0.1 (жёлтый #FFDA24, чёрный #171717, фон #FAFAF7). Брендбук Pic Pac 2025 (красный #DD5757, Futura PT) изучен, но основной стиль приложения — жёлто-чёрно-белый по решению команды.
- После правок бэкенда перезапустите uvicorn (без `--reload` код не подхватывается).

## Telegram Mini App
1. В Telegram откройте @BotFather → `/newbot` → скопируйте токен в `app/.env` (`TELEGRAM_BOT_TOKEN=...`). Токен никому не отправляйте и в репозиторий не добавляйте.
2. Запустите одной командой: `.venv/bin/python scripts/tma_start.py`. Она поднимает приложение на порту 8010, открывает бесплатный туннель cloudflared (`brew install cloudflared`, без аккаунта и без страницы-предупреждения; запасной вариант `TMA_TUNNEL=ngrok`, нужна авторизация ngrok) и настраивает бота: кнопка меню открывает Mini App, `/start` присылает кнопку запуска.
3. Вход идёт по подписи Telegram (`initData`, HMAC), пароли не нужны. После первого входа заказы привязаны к вашему Telegram-аккаунту, статусы приходят сообщениями от бота.
4. Без токена приложение работает как обычный сайт. Без туннеля Mini App не откроется: Telegram требует публичный HTTPS-адрес.
5. Публичный стенд: в `.env` стоят `SEED_TEST_USERS=0` и случайный `OPERATOR_PASSWORD` (логин `operator`). Тестовые демо-аккаунты в уже созданной базе остаются; для чистого стенда удалите `app/data/app.db`.
Ограничения: у бесплатных туннелей (cloudflared, ngrok) адрес меняется при каждом запуске, и кнопку меню бота скрипт обновляет сам; у Tailscale Funnel адрес постоянный. Стенд работает, пока включён компьютер с запущенным `scripts/tma_start.py`.

## Улучшение качества фото (AI-апскейл)
- Модель Real-ESRGAN `realesr-general-x4v3` (BSD-3-Clause, ~5 МБ), запускается локально через onnxruntime, фото никуда не передаётся. Установка: `.venv/bin/pip install onnxruntime numpy` и `.venv/bin/python scripts/fetch_models.py upscale`.
- Кнопки: редактор → вкладка AI → «Увеличить ×2/×4»; проверка перед печатью → «Улучшить качество (AI)» у фото с мало пикселей или размытых; AI-студия → «Улучшить».
- Увеличение обратимо: оригинал хранится отдельно, «Вернуть исходное качество» возвращает его. Правки (фильтры, кадр, текст) применяются поверх увеличенной версии.
- Ограничения: фото с длинной стороной больше 3200 px не увеличиваем (там уже хватает пикселей); результат не больше 7000 px; одно увеличение за раз. На ноутбуке 0,5–1,5 с на фото 500×400, около минуты на 12 Мп. Нейросеть дорисовывает детали, а не восстанавливает настоящие: на сильно смазанных кадрах результат лучше исходного, но не волшебный.

## Проверка качества и чистка подборки
Всё считается классическими алгоритмами (Pillow), без нейросетей и без отправки фото наружу. Эндпоинты: `GET /api/projects/{id}/check` (замечания, группы дубликатов, неудачные кадры), `POST /api/projects/{id}/cleanup` (`duplicates`/`bad`).
- Требуют внимания (нужно подтвердить перед заказом): мало пикселей для формата, размытость, тёмное, пересвет, дубликат, обрезка важного объекта.
- Советы (заказ не блокируют): блёклый кадр, цифровой шум, очень вытянутый кадр, сильное сжатие (похоже на пересылку через мессенджер), прозрачность PNG станет белой, WEBP/TIFF/BMP пересохранены в JPEG.
- Формат: принимаем JPEG, PNG, HEIC, WEBP, TIFF, BMP; GIF, SVG, PDF, RAW отклоняются с понятной причиной.
- Дубликаты: близкие перцептивный хэш, яркость, пропорции и миниатюра 24×24; из группы остаётся самый чёткий и крупный.
- Неудачные: сильно смазанные, почти чёрные, почти белые. Кнопки «Убрать дубликаты» и «Убрать неудачные» на шагах «Фото» и «Проверка».
- Обрезка: оценка по контрасту (где сосредоточены контуры), а не распознавание лиц. Сравниваем рамку «главного» с областью, уходящей под обрез в окне макета. Может ошибаться.
- Фото, загруженные до этой версии, досчитываются при первой проверке.
