# Переносимость: из Telegram Mini App в приложения (iOS, Android, macOS, Windows)

Статус на 11.11.2026. Это архитектура и подготовка, нативные сборки **не запускались**.

## Принцип
Один веб-интерфейс (`app/frontend`, без сборки) + один API (`app/backend`, FastAPI). Оболочки (Telegram, браузер/PWA, Capacitor, Tauri/Electron)
отличаются только тем, как запускают веб и как входит пользователь. Всё оболочно-зависимое сосредоточено в `platform` в `app/frontend/app.js`.

| Что | Telegram | Сайт / PWA | iOS, Android (Capacitor) | macOS, Windows |
|---|---|---|---|---|
| Интерфейс | тот же код | тот же код | тот же код (`mobile/www`) | тот же код (Tauri/Electron) |
| Адрес API | тот же домен | тот же домен | `PICPAC_API_BASE` в `config.js` + `CORS_ORIGINS` | то же |
| Вход | подпись `initData` | гость / логин | гость / логин (+ вход через Apple для App Store) | гость / логин |
| Кнопка «назад» | системная Telegram | стрелка в шапке | стрелка + событие `backbutton` | стрелка |
| Уведомления | бот Telegram | нет | нужны push (FCM/APNs), пока не сделаны | системные, не сделаны |
| Выбор фото | `<input type=file>` | то же | то же (позже: плагин камеры) | то же |

## Что сделано
- `platform` в `app.js`: `kind`, `initData()`, `ready()`, `setBack()`, `onBack()`. Остальной код не знает про Telegram.
- Адрес API вынесен в `config.js` (`PICPAC_API_BASE`), на сайте и в Telegram пусто.
- Сервер: `CORS_ORIGINS` и `PUBLIC_BASE_URL` (полные ссылки на файлы для нативных клиентов), оба по умолчанию выключены.
- PWA: `manifest.webmanifest`, иконки, `sw.js` (сначала сеть, кэш только запасной), метки для iPhone. Установка «на экран Домой» работает без магазинов.
- Каркас Capacitor: `mobile/` (конфиг, `sync.sh`, инструкция).

## Что осталось для «настоящего» приложения
1. Постоянный сервер с HTTPS (VPS или домен), иначе нативное приложение не к чему подключаться.
2. Push-уведомления вместо бота Telegram (FCM/APNs) и единая модель пользователя (сейчас связка через `tg_id`).
3. Вход через Apple/Google для магазинов, политика конфиденциальности, удаление аккаунта (удаление данных уже есть).
4. Нативные плагины: камера и галерея, шеринг, haptics, геолокация для ПВЗ.
5. Сборки и проверка на реальных устройствах, иконки и заставки в нужных размерах, подписание.
6. Хранилище файлов отдельно от диска приложения (S3-совместимое) и база с бэкапами (SQLite → PostgreSQL при росте).
7. Версионирование API (`/api/v1`) и OpenAPI-описание из FastAPI (`/docs`) как контракт для мобильных клиентов.

## Риски (гипотезы)
- iOS WebView и Telegram WebView ведут себя по-разному (мы уже получили баг `head`, исправлен изоляцией кода в функции).
- Загрузка больших фото из нативной галереи: нужен плагин и уменьшение до отправки (на вебе уже есть).
