**Остаётся:** «Пульс» и клиентское приложение в одном браузере хранят один токен — вход в «Пульс» выходит из клиентского аккаунта.

## 5. Smart Check — что реально вычисляется (WORKING)
Считает сервер по каждому фото при загрузке:
- **разрешение** под выбранный формат и размер ячейки макета (сколько пикселей нужно по длинной стороне);
- **потеря при кадрировании** под пропорции ячейки и попадание главного объекта в кадр;
- **яркость**: слишком тёмное, пересвеченное (доля выбитых пикселей), блёклое (контраст);
- **резкость** (размытость), **цифровой шум**;
- **дубли и почти дубли** (перцептивный хэш + сравнение мелких копий) с подсказкой, какое оставить;
- **файл**: формат (JPEG/PNG/HEIC), повреждённые и не-картинки отклоняются с причиной, >15 МБ отклоняется;
- по проекту: мало фото, нет макета, фото не помещаются, пустые страницы.
Блокирующие ошибки не дают заказать; предупреждения требуют явного подтверждения (409 без него).
**Не проверяет:** закрытые глаза, лица, смысл кадра.

## Простыми словами для комиссии

**Где хранятся фотографии и уходят ли наружу.** На нашем сервере (сейчас — Mac разработчика, папка `app/data/uploads`), в базе SQLite только метаданные. При загрузке файл пересохраняется — **EXIF с GPS-координатами удаляется**. Ссылки на фото подписаны и истекают. Фото **никуда не отправляются**: проверка качества и модерация — на сервере. Наружу уходит только текст: вопрос помощнику и номер/статус/сумма последних заказов (в Groq), текст описания для генерации (в Pollinations, если нет локальной модели), зашифрованный текст уведомления (в push-сервис браузера), сообщения бота (в Telegram). Пользователь может удалить аккаунт и все фото одной кнопкой.

**Что реально проверяет Smart Check.** См. п. 5: пиксели под формат, обрезку под ячейку, яркость, пересвет, контраст, резкость, шум, дубли, формат и целостность файла. Это расчёт по пикселям, а не «ИИ на глаз».

**Как устроены роли.** См. п. 2: роль хранится на сервере, каждый запрос проверяется сервером; интерфейс только прячет кнопки, но защищает сервер. Отказы пишутся в журнал.

**Что работает без интернета.** Сервер и всё приложение работают в локальной сети без интернета: загрузка, макет, правки, Smart Check, модерация, заказ, оператор, «Пульс». Без интернета не работают: помощник через Groq (переходит на ответы по правилам), push и Telegram, генерация через Pollinations. В приложении есть режим «Имитировать отсутствие сети»: черновик сохраняется, ничего не зависает. Офлайн-режима **на телефоне** (работа без связи с сервером) нет — ROADMAP.

**Архитектура и масштабирование.** Один сервер FastAPI (Python) + SQLite + статический фронтенд без сборки; один код для Telegram, браузера и PWA; тяжёлые модели — отдельные модули, грузятся по наличию. Масштабирование: SQLite → PostgreSQL, файлы → объектное хранилище (S3-совместимое), модели — в отдельный сервис-очередь, несколько копий API за балансировщиком (сессии уже в базе, сервер их не держит в памяти), Telegram-бот — на вебхук. Это план, **не проверено под нагрузкой**.

**Как защищён повтор заказа.** Приложение создаёт уникальный ключ `Idempotency-Key` для каждой попытки оформления. Сервер хранит его вместе с заказом (уникально для пользователя). Повтор того же запроса — например, после обрыва связи — возвращает **тот же заказ**, а не новый. Без ключа заказ не принимается (400). Проверено: имитация обрыва после сохранения → повтор → один заказ (аудит F1–F5, тест N7–N8).

**Что из «Мэри», дашборда и push подключено на самом деле.** Мэри — имитация на открытой модели, реальная не подключена. Дашборд «Пульс» — работает, но 10 из 12 показателей на синтетике (помечены MOCK). Push — сервер отправляет и шифрует, Google принимает; Telegram-бот работает; показ на iPhone не подтверждён.
