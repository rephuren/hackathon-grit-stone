# Задачи по визуальному обновлению

Статус этого файла: передача задач. Реализация должна идти через обычную координацию `.team/`, отдельную ветку и Pull Request.

## P0. Зафиксировать тему через токены

- [ ] Сопоставить существующие переменные в `app/frontend/styles.css` и `app/frontend/theme.css` с `DESIGN_TOKENS.md`.
- [ ] Не размазывать hex-значения по компонентам: общие цвета должны жить в переменных.
- [ ] Сохранить текущие режимы `system / light / dark` и восстановление выбора после перезапуска.
- [ ] Не затрагивать API и бизнес-логику.

Критерий: переключение темы не меняет разметку, не сбрасывает проект и не требует перезагрузки.

## P0. Четыре контрольных экрана

### Главная

- [ ] Заменить доминирующий жёлтый на тёплый фон, зелёно-графитовый текст и коралловый CTA.
- [ ] Сохранить робота, блок создания продукта, AI-действие, продолжение проекта и нижнюю навигацию.
- [ ] Не менять маршруты и обработчики действий.

### Проекты

- [ ] Привести карточки, бейдж `Черновик`, кнопку создания и навигацию к новым токенам.
- [ ] Сохранить все данные, даты, превью и переходы.
- [ ] Проверить длинные названия без обрезки важных действий.

### Пустая корзина

- [ ] Корзина при первом открытии остаётся пустой.
- [ ] Сохранить два действия: выбор продукта и продолжение незавершённого проекта.
- [ ] Не добавлять демонстрационный товар автоматически.

### Профиль

- [ ] Перекрасить меню, селектор темы, toggle, демо-настройки и аккаунтные действия.
- [ ] Сохранить опасное действие визуально отдельным и явно разрушительным.
- [ ] Проверить светлую, тёмную и системную тему.

Критерий: каждый экран визуально соответствует паре из `references/light` и `references/dark`, но повторяет структуру исходного экрана.

## P1. Распространить систему на остальные экраны

- [ ] Каталог шаблонов и карточки товаров.
- [ ] Загрузка фотографий и AI-мастерская.
- [ ] Редактор, инструменты и ползунки.
- [ ] Проверка качества, предупреждения и подтверждения.
- [ ] Оформление TEST-заказа, статусы и поддержка.
- [ ] AI-помощник Робо.

Для этих экранов не создавать новую композицию: применять те же токены к существующим компонентам.

## P1. Проверка качества

- [ ] 360, 375 и 390 px: нет горизонтального скролла и наложений.
- [ ] Все интерактивные цели не меньше 44 x 44 px.
- [ ] Контраст текста и контролов не ниже WCAG AA, где применимо.
- [ ] Клавиатурный `focus-visible` заметен в обеих темах.
- [ ] Safe-area и установленная PWA не получают цветных разрывов сверху и снизу.
- [ ] Offline, loading, disabled, success и error читаемы в обеих темах.
- [ ] Превью печатного продукта не становится тёмным.
- [ ] Прогнать существующие тесты и сквозной обязательный путь до TEST-заказа.

## Не входит в эту передачу

- полный редизайн экранов;
- изменение архитектуры или API;
- написание новых промптов для Claude;
- подключение платных сервисов;
- добавление PDF/DOCX брендбука и других материалов заказчика в GitHub.
