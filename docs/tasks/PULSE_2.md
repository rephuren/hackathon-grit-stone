# Задание kent (Глеб + Codex), часть 2 — «Пульс PicPac»: один сквозной управленческий сценарий

Основа: `docs/tasks/PULSE.md` (первая часть уже в `main`, модуль слит, 38 тестов зелёные). Уточнение тимлида: **не десять графиков, а один работающий сценарий** и честный статус. Клиентское приложение не ломаем.

## Целевой сценарий (должен проходиться руками и тестом)
1. Клиент в PicPac создаёт проект и TEST-заказ.
2. Заказ (и события воронки) появляется в «Пульсе» как **реальные** данные, отдельно от синтетики.
3. «Пульс» показывает KPI и отклонение (красное).
4. Администратор открывает проблемный KPI → видит первичные данные (до строки заказа, с id заказа).
5. Создаёт решение: причина, ответственный, срок, статус.
6. Решение сохраняется, журнал изменений ведётся.
7. После исправления результат **можно перепроверить**: на карточке решения видно «значение KPI при создании → значение сейчас».

## Что сделать (в порядке важности)
1. **Реальные заказы в «Пульсе».** Проверить `pulse_data.order_rows`: заказ, созданный через клиентское приложение (таблица `orders`), должен попадать в KPI оборот/средний чек/заказы и в детализацию с пометкой `data: "real"`. Если сейчас только синтетика — добавить чтение `orders` (только чтение; наши таблицы и `main.py` не менять).
2. **Детализация до заказа.** Drill красного KPI доходит до списка заказов с номерами (`PP-000004`), суммой, статусом, подразделением. Реальные заказы отличимы от синтетических.
3. **Перепроверка результата (шаг 7).** При создании решения сохранять `kpi_value_at_create`; при переводе в `verified` (и по кнопке «Перепроверить») пересчитывать KPI и записывать в `pulse_decision_log` «было → стало». Показать в карточке.
4. **Пять систем по первичному ТЗ: CRM, поддержка, производство, финансы, персонал.** Сейчас есть ERP-заказы, MES, 1С, HR и реальные обращения (`tickets`). Не хватает явного **CRM**: добавить синтетическую `pulse_crm` (клиенты с `customer_id`, сегмент, канал, дата первой покупки), связать с заказами по `customer_id`, KPI «новые/повторные клиенты» считать из неё. На экране «Источники» (analyst) показать все пять с временем обновления, пропусками и дублями. Всё помечено MOCK, кроме `tickets` и `events`.
5. **Отдельный ключ токена `pp_pulse_token`** в `pulse.js` вместо `pp_token`: сейчас вход в «Пульс» выкидывает клиентский аккаунт из приложения в том же браузере.
6. **Доказательства**: скриншоты каждого шага сценария и короткое видео (до 60 с) одного полного прохода → `docs/evidence/pulse/` (PNG, MP4). Без реальных персональных данных.
7. **Ответы на 8 вопросов тимлида** — одним файлом `docs/tasks/PULSE_FACTS.md`, коротко, по фактам кода (я перенесу в TECH FACT LOCK):
